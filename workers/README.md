# Ringmaster Workers

Ringmaster workers are **self-contained bash scripts** generated by AI. Each worker is fully configured with its behavior baked into the script.

## How It Works

1. **Describe** the worker you want in natural language
2. **AI generates** a complete bash script with all behavior coded in
3. **Deploy** the worker - it polls for tasks and processes them
4. **No configuration files** - everything is in the generated script

## Creating Workers

### Via Ringmaster UI (Recommended)

1. Go to http://localhost:8080/workers
2. Click "+ New Worker"
3. Enter a name and description
4. Click "Edit" on the new worker
5. Use "Generate Script from AI" with a description like:
   ```
   A Python backend developer worker focused on FastAPI and SQLAlchemy
   ```
6. Review/edit the generated script
7. Save

The generated script will be fully self-contained - no separate config files needed.

### Via API

```bash
# Using local Claude Code CLI (preferred - uses your existing auth)
curl -X POST http://localhost:8080/api/settings/create-worker \
  -H "Content-Type: application/json" \
  -d '{
    "natural_language": "Frontend worker for React and TypeScript development",
    "worker_id": "frontend-dev-1"
  }'
```

## Worker Script Structure

Generated workers follow this pattern:

```bash
#!/bin/bash
set -euo pipefail

WORKER_ID="${1:-}"
RINGMASTER_API="http://localhost:8080/api"

# Worker behavior is BAKED IN to the script
# No config files or environment variables needed

get_next_task() {
    curl -s "${RINGMASTER_API}/workers/${WORKER_ID}/next-task"
}

process_task() {
    local task_json="$1"
    local task_id task_prompt

    task_id=$(echo "$task_json" | jq -r '.id')
    task_prompt=$(echo "$task_json" | jq -r '.prompt')

    log "Task: $task_prompt"

    # Execute Claude Code with worker-specific behavior
    cd "${WORKING_DIR:-.}" || exit 1

    # The worker's specialization is coded here:
    claude --prompt "${task_prompt}

Focus on Python backend development:
- Use FastAPI or Flask as appropriate
- Write SQLAlchemy models with proper relationships
- Add type hints throughout
- Include pytest tests
- Follow PEP 8 conventions
" || true

    # Report completion
    curl -s -X POST "${RINGMASTER_API}/workers/${WORKER_ID}/complete" \
        -H "Content-Type: application/json" \
        -d '{"task_id": "'"${task_id}"'", "success": true}'
}

# Main worker loop
trap 'log "Shutting down..."; exit 0' SIGINT SIGTERM

while true; do
    local task=$(get_next_task)
    if [ "$task" != "null" ] && [ -n "$task" ]; then
        process_task "$task"
    fi
    sleep 5
done
```

## Key Features

- **Self-contained**: All behavior is in the script, no external configs
- **Generated by AI**: Describe what you want, get a working script
- **Flexible**: Supports any AI coding tool (Claude Code, Aider, Cursor, etc.)
- **Multiple auth methods**: API keys, monthly plans, local CLI auth
- **Editable**: You can manually edit generated scripts

## Authentication

Workers support multiple authentication methods:
- **Monthly Plans**: Claude Code Pro, Cursor Pro - tool handles auth
- **API Keys**: Set as environment variables if needed
- **Local CLI Auth**: Uses existing authenticated sessions
- **Config Files**: Reads from ~/.config/

## Creating Workers Manually

While AI generation is recommended, you can also create workers manually by writing the bash script yourself and pasting it into the worker's "Generated Start Script" field.

**Benefits:**
- No code changes needed to configure workers
- Behavior defined in natural language
- Easy to create specialized workers (frontend, backend, security, testing, etc.)
- Works with any Claude Code authentication (API key, monthly plan, etc.)

1. Go to http://localhost:8080/workers
2. Click "+ New Worker"
3. Enter a name and description

## Launcher Script Usage

### Environment Variables

When a worker uses a launcher script, Ringmaster sets:

- `RINGMASTER_PROMPT_FILE` - Path to file containing the enriched prompt
- `RINGMASTER_WORKING_DIR` - Working directory for the task
- `RINGMASTER_TASK_ID` - Task/bead identifier
- `RINGMASTER_WORKER_ID` - Worker identifier
- `RINGMASTER_LOG_FILE` - Path to worker log file
- `RINGMASTER_LAUNCHER_SCRIPT` - Path to the launcher script itself
- `RINGMASTER_LAUNCHER_ARGS` - Additional arguments for the launcher

### claude-code-launcher.sh

**Environment Variables:**
- `CLAUDE_MODEL` - Model to use (default: `claude-sonnet-4-20250514`)
- `CLAUDE_CONFIG_DIR` - Path to Claude Code config directory
- `CLAUDE_MAX_TOKENS` - Maximum tokens for requests (default: 200000)

**Usage:**
```bash
ringmaster worker spawn claude-1 \
  --type claude-code \
  --launcher-script /path/to/ringmaster/workers/claude-code-launcher.sh \
  --capabilities python typescript
```

### claude-max-launcher.sh

**Environment Variables:**
- `CLAUDE_MAX_MODEL` - Model to use (default: `claude-sonnet-4-20250514`)
- `CLAUDE_MAX_API_KEY` - API key for Claude Max account
- `CLAUDE_MAX_BASE_URL` - Base URL for Claude Max API endpoint

**Usage:**
```bash
export CLAUDE_MAX_API_KEY="your-api-key"
export CLAUDE_MAX_BASE_URL="https://your-custom-endpoint.com"

ringmaster worker spawn claude-max-1 \
  --type claude-code \
  --launcher-script /path/to/ringmaster/workers/claude-max-launcher.sh \
  --capabilities python rust
```

### zai-glm-launcher.sh

- `ZAI_API_KEY` - API key for Z.AI
- `ZAI_BASE_URL` - Base URL for Z.AI API (default: `https://api.z.ai/v1`)

## Creating Custom Launcher Scripts

You can create your own launcher scripts for any coding agent. Here's a template:

```bash
#!/bin/bash
# My Custom Worker Launcher

set -euo pipefail

# Read Ringmaster environment variables
PROMPT_FILE="${RINGMASTER_PROMPT_FILE}"
WORKING_DIR="${RINGMASTER_WORKING_DIR}"
TASK_ID="${RINGMASTER_TASK_ID}"

# Your custom configuration
MY_API_KEY="${MY_API_KEY:-}"
MY_MODEL="${MY_MODEL:-}"

# Change to working directory
cd "$WORKING_DIR" || exit 1

# Read the prompt
PROMPT=$(cat "$PROMPT_FILE")

# Execute your coding agent
my-coding-agent \
  --model "$MY_MODEL" \
  --api-key "$MY_API_KEY" \
  --prompt "$PROMPT"
```

## Inline Launcher Scripts

Instead of a separate file, you can store launcher script content directly in the worker configuration:

```python
from ringmaster.db import WorkerRepository, get_database
from ringmaster.domain import Worker

async def create_worker_with_inline_script():
    db = await get_database()
    repo = WorkerRepository(db)

    inline_script = '''#!/bin/bash
# Custom inline launcher
cd "$RINGMASTER_WORKING_DIR" || exit 1
my-agent --prompt "$(cat $RINGMASTER_PROMPT_FILE)"
'''

    worker = Worker(
        name="custom-worker",
        type="launcher",
        launcher_script_inline=inline_script,
        capabilities=["python"],
    )
    await repo.create(worker)
```

## Troubleshooting

### Script not executable
```bash
chmod +x /path/to/your-launcher.sh
```

### Environment variables not set
Ensure the launcher script reads from the expected environment variables. Check the worker's log file for details.

### API key issues
Make sure API keys are exported before spawning the worker, or set them in your shell profile (`.bashrc`, `.zshrc`).

### Claude Code CLI not found
Install the Claude Code CLI:
```bash
npm install -g @anthropic-ai/claude-code
```
